# 分区文件加密密钥轮换系统

一批分区文件的加密密钥需要轮换，后台逐文件重写期间查询仍要读到一致的数据版本。
本项目用 Python 标准库从零实现真实的认证加密、密钥版本登记、后台轮换编排和
查询下载服务，附带网页控制台与端到端测试。

## 架构与三个协作者

| 模块 | 职责 |
| --- | --- |
| `key_rotation/crypto.py` | 文件加工器的加解密原语：HKDF-SHA256 派生 + HMAC-SHA256 计数器流加密 + Encrypt-then-MAC（纯标准库，真实加密，非占位） |
| `key_rotation/keyring.py` | 密钥版本登记：唯一存放主密钥的地方，0600 私有 JSON，状态机 active → retired → disabled，含在途下载引用计数 |
| `key_rotation/storage.py` | 加密分区存储 + 逐文件清单：原子重写（临时文件 + `os.replace`），清单与数据在同一把锁内一起更新 |
| `key_rotation/rotation.py` | 后台轮换编排：逐文件工作线程，支持暂停/恢复、失败重试、故障注入与备份恢复 |
| `key_rotation/webapp.py` + `static/index.html` | 查询下载服务与网页控制台（`http.server`，无第三方依赖） |
| `key_rotation/log_security.py` | 日志脱敏：注册密钥精确匹配 + 高熵串模式兜底，密钥字节不进日志 |

## 关键设计决策（对应需求逐条落实）

### 1. 清单标明每个文件实际所用版本，不搞全局密钥号

每个加密文件的容器头里写着它自己的 `key_version`（如 `v2`），
`manifest.json` 逐文件镜像该版本；读取时**以文件头里的版本为准**去密钥登记取密钥，
而不是查一个全局"当前密钥号"。因此 v1/v2 混合的文件群随时都能正确解密。

### 2. 后台逐文件重写时查询的一致性

- 重写先写临时文件 `*.writing`，完整加密并落盘后 `os.replace()` 原子替换，
  并发查询只能看到**完整旧版或完整新版**，绝不会读到半成品。
- 清单替换与数据替换在同一把存储锁内完成，两者不可能分叉；
  启动时还有 `reconcile_manifest()` 按磁盘文件头校正清单（崩溃恢复）。
- 测试中 4 个读线程在轮换全程高频查询，0 次不一致（见测试 2-4）。

### 3. 整版切换 vs 兼容混合（两种策略都支持，网页可选）

- **兼容混合（mixed）**：逐文件迁到新密钥，旧密钥保持 active，
  当前加密密钥不变；迁移中和迁移后文件群合法混合。
- **整版切换（cutover）**：同样逐文件重写，但只有**全部文件成功**后，
  才把目标密钥设为当前加密密钥，并把旧 active 密钥自动转为 retired（仅解密）。
  只要有一个文件失败，切换扣留：不退役任何密钥，文件群保持混合，
  恢复并重试成功后才完成切换。

### 4. 密钥停用与旧下载在读的关系（明确规则）

密钥停用 = **销毁密钥本体**，状态机 `active/retired → disabled`，
仅当两个条件同时满足才允许：

1. 文件引用数 = 0（按实际文件头统计，不看清单）；
2. 在途下载数 = 0（下载开始时 `begin_use` 钉住该版本，结束才释放）。

当前加密密钥永远不可停用。停用后 `secret_b64` 清空，任何解密立即失败，
不可恢复——所以旧密钥只要还有合法引用就只能 retired（仅解密），不能 disabled。

### 5. 密钥只在本地私有配置，不进下载包和日志

- 密钥只写在 `demo_env/private/keyring.json`，权限 0600、目录 0700；
  已加入 `.gitignore`。
- 下载 ZIP 只含明文 CSV + `MANIFEST.json`（数据清单，无密钥、无 nonce、无容器），
  生成后还有运行时断言：包里出现任何已登记密钥字节就拒绝发送。
- 所有日志经 `SecretRedactionFilter`：精确匹配已注册密钥 + base64/hex 高熵模式兜底。

## 网页控制台操作

`http://127.0.0.1:8000/` 上可完成：登记新密钥、选择策略启动轮换、暂停/恢复、
重试失败文件、对单个文件注入篡改（校验真实失败）并从备份恢复、查看每个文件的
实际密钥版本与校验状态、查看仍有合法引用的旧密钥、退役/停用密钥、查询明文和下载。

## 运行方式

```bash
# 1. 初始化虚构数据（8 个分区文件，全部以 v1 真实加密）
python3 -I tools/seed_demo.py --base-dir demo_env

# 2. 启动服务（默认 127.0.0.1:8000）
python3 -I tools/run_server.py --base-dir demo_env --port 8000 --log demo_env/service.log

# 3. 端到端测试（47 项，临时目录，不碰 demo_env）
python3 -I tools/run_tests.py

# 4. HTTP 全流程冒烟（需先起服务）
python3 -I tools/smoke_http.py http://127.0.0.1:8000
```

所有 Python 均以 `-I`（隔离模式）运行，避免当前目录被植入模块劫持。

## 加密容器格式（KRT1）

```
magic "KRT1" | 格式版本 | key_version(变长) | 16B 随机 nonce |
明文长度 | 密文（HMAC-SHA256 计数器流，块=32B）| 32B 认证标签
```

- 每文件独立随机 nonce，经 HKDF-SHA256 派生数据密钥与认证密钥；
- 认证标签覆盖 `文件头 + AAD(文件ID, 密钥版本) + 密文`，
  改一个密文字节、换文件、换密钥版本都会在 HMAC 校验处真实失败；
- AAD 绑定逻辑文件 ID，加密容器无法被搬到别的分区文件上仍通过校验。
